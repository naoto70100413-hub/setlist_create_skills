# ダンスイベント セットリスト作成スキル

## 概要

出演チームリスト（Excel/CSV）を入力として、制約を満たす最適な出演順に並び替え、
時刻入りスケジュール表（Excel）を生成する。
`scripts/generate_setlist.py` を使って一括処理する。

出演順の最適化には **OR-Tools（CP-SAT）による厳密探索**を使用する（`pip install ortools`
が必要）。ortoolsが使えない環境では自動的に貪欲法（近似解）にフォールバックする。
CP-SATは組み合わせを網羅的に探索するため、貪欲法より局所最適に陥りにくく、
特に掛け持ち制約が複雑に絡み合う場合により良い解を見つけやすい。

---

## 入力データ形式

| 列名（デフォルト） | 内容 | 例 |
|---|---|---|
| 受付番号 | 申込の受付番号（任意、なくても動作する） | 001 |
| チーム名 | チームの名前 | TEAM_A |
| 曲名 | 演技で使用する曲 | ダンシングクイーン |
| アーティスト名 | 曲のアーティスト | ABBA |
| 掛け持ちチーム | 共通メンバーがいる他チーム（カンマ区切り） | TEAM_C, TEAM_E |
| 希望時間帯 | 出演したい時間帯（自由記述可） | 前半 / 後半 / なるべく早めがいい / 15時までに終わりたい 等 |

列名が異なる場合は `--col-*` オプションで上書きできる。

---

## 実行手順

### Step 1: 入力確認

ユーザーから以下を確認する（まだ得ていない場合）:
1. **入力ファイルのパス**（Excel/CSV）
2. **イベント開始時刻**（例: `13:00`）

### Step 2: スキルのディレクトリを特定する

このSKILL.mdが置かれているディレクトリのパスを `SKILL_DIR` とする。
Claude Codeでは `SKILL.md` の絶対パスから親ディレクトリを取得することで特定できる。

### Step 3: Spotify で再生時間を取得する

`anthropic-skills:spotify-duration` スキルを使って全チームの再生時間を事前に取得する。

**3-1: 曲リスト CSV を作成する**

入力ファイルを読み込み、`/tmp/setlist_songs.csv`（列: チーム名・曲名・アーティスト名）を生成する。
列名が異なる場合は実際の列名に置き換えること。

```bash
python3 -c "
import pandas as pd
from pathlib import Path
path = Path('<入力ファイルパス>')
df = pd.read_excel(path) if path.suffix in ('.xlsx','.xls') else pd.read_csv(path)
df = df.rename(columns={'<チーム名列>': 'チーム名', '<曲名列>': '曲名', '<アーティスト名列>': 'アーティスト名'})
df[['チーム名','曲名','アーティスト名']].to_csv('/tmp/setlist_songs.csv', index=False, encoding='utf-8-sig')
print('Exported', len(df), 'songs to /tmp/setlist_songs.csv')
"
```

**3-2: spotify-duration スキルを呼び出す**

`anthropic-skills:spotify-duration` スキルを呼び出し、`/tmp/setlist_songs.csv` に再生時間を追記してもらう。

**3-3: `--duration-overrides` JSON を組み立てる**

取得後のCSVを読み込んで `{"チーム名": 秒数}` の JSON を生成する。

⚠ **単位に注意**: `--duration-overrides` はミリ秒(ms)ではなく**秒**を渡す。
Spotify APIは`duration_ms`（ミリ秒）を返すため、そのまま渡すと出演時間が
「52時間」等の異常値になりスケジュール全体が破綻する。以下のスクリプトは
値の大きさから ms/秒 を自動判定するが、判定が誤っていないか目視確認すること
（generate_setlist.py 側でも1200秒＝20分を超える値には警告を出す安全策がある）。

```bash
python3 -c "
import pandas as pd, json, sys
df = pd.read_csv('/tmp/setlist_songs.csv')
dur_cols = [c for c in df.columns if c not in ('チーム名','曲名','アーティスト名')]
result, missing = {}, []
if dur_cols:
    dc = dur_cols[-1]
    for _, row in df.iterrows():
        val = str(row[dc]).strip()
        if not val or val in ('nan','None',''):
            missing.append(str(row['チーム名'])); continue
        try:
            if ':' in val:
                parts = val.split(':')
                secs = int(parts[-2]) * 60 + int(parts[-1])
            else:
                v = int(float(val))
                # duration_ms(ミリ秒)がそのまま来た場合に備え、
                # 現実的な出演時間(20分=1200秒)を大きく超える値はms→秒に変換する
                secs = v // 1000 if v > 1200 else v
            result[str(row['チーム名'])] = secs
        except:
            missing.append(str(row['チーム名']))
if missing:
    print('MISSING:', missing, file=sys.stderr)
print(json.dumps(result, ensure_ascii=False))
"
```

取得できなかったチームがあれば、ユーザーに再生時間（分:秒）を手動で確認し、秒数に変換して JSON に追加する。

### Step 4: 希望時間帯の自由記述を解釈する

入力ファイルの「希望時間帯」列を読み、各チームの記述を以下のいずれかに正規化する
（前半/後半の単純な記述はスクリプト側でも自動判定できるが、それ以外の自由記述は
このステップで解釈しないと反映されない）。

| type | 意味 | 元の記述の例 |
|---|---|---|
| `first` | 前半希望 | 「前半がいい」 |
| `second` | 後半希望 | 「後半で」 |
| `early` | できるだけ早め希望（連続的） | 「なるべく早い時間がいい」「早めだと助かる」 |
| `late` | できるだけ遅め希望（連続的） | 「遅めで大丈夫」「最後の方でOK」 |
| `before` | 指定時刻より前に出演/終演したい（`time`必須, `HH:MM`） | 「15時までに終わりたい」「14時半より前がいい」 |
| `after` | 指定時刻より後に出演したい（`time`必須, `HH:MM`） | 「16時以降がいい」 |
| `block` | ○部を厳密に指定（`block`必須, 1始まりの整数） | 「2部がいい」「後半の部で」 |

`block`は**非推奨**: ブロック数(`--n-blocks`)を変更すると指定がズレて悪化する
（例:「3部」希望がブロック数変更で意味の異なる位置になる）。「○部」という
記述があっても、可能な限り `first`/`second`/`early`/`late` 等ブロック数に
依存しない表現に変換すること。ブロック数を変えない前提が確実な場合のみ使う。

「指定なし」「特になし」「空欄」などは対象外（正規化しない＝希望なしとして扱う）。
判断に迷う記述があれば、正規化せずに元のテキストのまま扱って構わない（その場合は
前半/後半の単純一致のみが自動反映される）。

`before`/`after` は「達成できたか」の二値ではなく、**指定時刻とのズレの大きさ**も
評価に反映される。ズレが小さいほど高スコア（例: 18時以降希望で17:30配置は17:00配置より
高評価、17:00配置は16:00配置より高評価）。ズレが大きいほど評価は下がり続けるが、
達成できている場合は余裕の大小に関わらず同一の満点として扱われる。

解釈結果を `{"チーム名": {"type": "...", "time": "HH:MM"}}` 形式のJSON（`--pref-overrides`）
にまとめる。前半/後半以外の希望が無ければこのオプションは省略してよい。

### Step 5: スクリプト実行

**初回実行時から、掛け持ち間隔・希望時間帯・曲/アーティスト連続の3つを
すべてハード制約として試みる**（`--hard-pref --hard-min-shared-gap --hard-similarity`
を常に付ける）。全てを満たす解が見つからない場合はスクリプトが自動的に、
優先度の低いもの（希望時間帯 → 曲/アーティスト連続 → 掛け持ち間隔の順）から
ソフト制約へ緩和して再探索するため、段階的に手動でオプションを組み替える必要はない。

```bash
PYTHONIOENCODING=utf-8 python3 "<SKILL_DIR>/scripts/generate_setlist.py" \
  --input "<入力ファイルパス>" \
  --start-time "<開始時刻 例:13:00>" \
  --output "<出力ファイルパス 例:setlist_YYYYMMDD.xlsx>" \
  --duration-overrides '<Step 3-3 で生成した JSON>' \
  --pref-overrides '<Step 4 で生成した JSON（任意）>' \
  --hard-pref --hard-min-shared-gap --hard-similarity
```

列名が違う場合は追加オプションを付ける:
```bash
  --col-id "No"            # 受付番号列のヘッダー
  --col-team "Team"       # チーム名列のヘッダー
  --col-song "Song"       # 曲名列のヘッダー
  --col-artist "Artist"   # アーティスト名列のヘッダー
  --col-shared "Shared"   # 掛け持ちチーム列のヘッダー
  --col-pref "Pref"       # 希望時間帯列のヘッダー
```

ブロック数を固定したい場合:
```bash
  --n-blocks 4  # デフォルト: チーム数15以下→4、16以上→5
```

その他のオプション:
```bash
  --time-limit-sec 60      # CP-SATの1回あたり探索時間(秒)。デフォルト60。
                           # 70チーム超では120〜270秒程度を確保すること
                           # （短いと明らかに悪い解になりやすい）
  --hard-pref              # 希望時間帯(first/second/before/after/block)をハード制約にする
  --hard-min-shared-gap    # 掛け持ち間隔の最低ライン(40分)をハード制約にする
  --hard-similarity        # 曲・アーティストの最低間隔(2組)をハード制約にする
                           # ↑3つとも指定するのが基本（Step 5参照）。全て満たす解が
                           # 見つからない場合は優先度の低いものから自動的にソフト制約へ
                           # 緩和され、標準エラー出力に緩和した項目が表示される
  --shared-ideal-off       # 掛け持ち間隔の「1時間が理想」という上乗せの目的関数
                           # 項を無効化し、40分死守（or 40分への到達）のみを目的にする
  --fixed-order-file FILE  # 事前に決定済みの出演順(チーム名のJSON配列)を読み込み、
                           # 最適化をスキップしてレポート生成のみ行う
  --seed N                 # 貪欲法フォールバック時のみ有効。タイブレークをランダム化する
```

ortoolsが使える環境ではCP-SATによる厳密探索が使われるため、多くの場合1回の実行で
十分良い（あるいは最適な）結果が得られる。ただしCP-SATの探索結果は探索時間に対して
**非単調**（探索時間を伸ばすと必ず改善するとは限らない）であり、時間内に最適性を
証明できなかった場合は実行のたびに多少ばらつくことがある。ortoolsが無く貪欲法に
フォールバックした場合（実行時に`[Info] ortools が未インストールのため貪欲法...`と
出力される）は常に唯一の最適解を保証しない。掛け持ちペアが複数あって`WARNING`
（掛け持ち間隔不足・曲/アーティストの連続）が出た場合は、Step 5-1 で複数回試して
最良のものを選ぶ。

### Step 5-1: 警告が出た場合の複数回試行（推奨）

Step 5 の出力末尾に `QUALITY_SUMMARY: warn=N note=M min_shared_gap_sec=S` という行が
出力される。`warn`（要対応の違反件数）が0でない場合、同一設定のまま複数回
（目安3〜5回、70チーム超では`--time-limit-sec`を120〜270秒にして）再実行し、
`QUALITY_SUMMARY`を比較して最良のもの（優先順: warnが最小 → 同点ならnoteが最小 →
同点ならmin_shared_gap_secが最大）を採用する。貪欲法フォールバック時は`--seed`を
1〜10で変えて同様に比較する。`--output`は試行ごとに一時ファイルへ出し、最良
だったものを最終的な出力ファイルパスにコピー（または同条件で最後にもう一度実行）
すること。

```bash
for i in 1 2 3 4 5; do
  PYTHONIOENCODING=utf-8 python3 "<SKILL_DIR>/scripts/generate_setlist.py" \
    --input "<入力ファイルパス>" --start-time "<開始時刻>" \
    --output "/tmp/setlist_trial_${i}.xlsx" --time-limit-sec 120 \
    --duration-overrides '<JSON>' --pref-overrides '<JSON>'
done
```

warnが0にならない場合でも、試行回数の上限（5〜10回程度）に達したら探索を打ち切り、
その時点で最良の案を採用し、残った警告は正直にユーザーへ報告する。
（掛け持ち制約が物理的に満たせない入力であれば、何回試しても解消しないことに注意）

### Step 5-2: 全ハード制約が緩和された場合（任意、上級者向け）

Step 5 で3つとも指定していれば、スクリプトは内部で自動的に
「全ハード → 希望時間帯を緩和 → 曲/アーティスト連続も緩和 → 掛け持ち間隔も緩和」
の順に段階的に緩和しながら解を探すため、通常は手動でオプションを組み替える必要はない。
標準エラー出力に `[CP-SAT] 要求された全ハード制約では解が見つからなかったため、
優先度の低い順にソフト制約へ緩和しました（緩和した項目: ...）` と出力された場合、
どこまで緩和されたかを確認し、以下を検討する。

- 緩和が「希望時間帯」だけなら、多くの場合は許容範囲（希望が完全には通らなかった
  だけ）としてそのまま報告してよい
- 「掛け持ち間隔」まで緩和された場合は、チーム数・出演時間に対して40分の間隔を
  確保するための物理的な時間が足りていない可能性が高い。`--time-limit-sec`を
  120〜270秒に伸ばして再実行しても改善しないなら、根本的に時間が足りないことを
  ユーザーに伝える
- 特定のチームだけどうしても解消しない場合、そのチームの希望時間帯の原文に
  「掛け持ちが多いので可能な範囲で」等の緩和表現がないか確認し、あれば
  そのチームの希望だけ`--pref-overrides`から除外するなど例外扱いを提案する

### Step 5-3: 手動で決めた出演順をレポート化したい場合

局所探索やユーザー自身の判断で既に出演順が決まっている場合は、`--fixed-order-file`
にチーム名のJSON配列（例: `["TEAM_C","TEAM_A","TEAM_B"]`）を渡すと、最適化を
スキップしてその順序のままチェック・Excel生成のみ行う。

### Step 6: 結果報告

- 生成されたExcelファイルのパスをユーザーに伝える
- スクリプトが出力するサマリー（チーム数・ブロック数・終了時刻・警告）を表示する
- 複数パターンを試した場合は、何パターン試して何が改善したか（または改善しなかったか）を伝える
- ⚠ 警告がある場合（掛け持ち制約の違反・再生時間未取得の曲）は目立つように伝える

## スケジューリング制約（優先順位順）

1. **掛け持ちチーム間隔（最優先）**: 掛け持ちメンバーのいるチーム同士は基本 **1時間**、最低でも **40分** の間隔
   - 出演順を決める段階で、間にブロック間休憩（最低10分）が挟まる配置は、その分の時間も間隔に加算して評価する。休憩を挟む配置を活用することで、より少ないチーム数の間隔で1時間に近づけられるようにする
   - 40分未満になった場合のみ ⚠ 違反として扱う（40分〜1時間は「許容」）
   - 物理的に40分も満たせない場合: 複数ペアの間隔をできるだけ均等化（例: A-B 10分・B-C 60分より A-B 35分・B-C 35分を優先）し ⚠ 警告を出力
2. **曲・アーティストの連続回避（2番目）**: 同じ曲・同じアーティストのチーム同士は、最低 **2組** 空ける（間に2チーム以上を挟む）
3. **ブロック均等割り**: 全チームを 4〜5 ブロックに均等分割（端数は先頭ブロックへ）
4. **ブロック間休憩**: 最低 **10分** 確保しつつ、次ブロックは **15分刻み（00/15/30/45分）** のキリの良い時刻に開始（休憩が15分未満でもよい）
5. **チーム間インターバル**: チーム間は **30秒** の入退場インターバル
6. **希望時間帯（ソフト制約、最下位）**: 前半/後半/できるだけ早め/できるだけ遅め/指定時刻より前後、といった希望を可能な範囲で反映（Step 4 の解釈結果に基づく）

**文句なしにクリア（掛け持ち間隔が1時間以上・曲/アーティスト間隔が2組以上・希望時間帯どおり）していないチームは、
達成の程度を問わず全て出力Excelの備考欄に理由を記載する。**深刻度は2段階:

- **warn（要対応）= 黄色背景**: 掛け持ち間隔が40分未満、または曲/アーティストが2組未満しか空いていない（明確なルール違反）
- **note（参考）= 水色背景**: 掛け持ち間隔は40分以上あるが1時間の目安には届いていない、または希望時間帯どおりに配置できなかった（許容範囲だが完全ではない）

## 出力 Excel の構成

### Sheet1: セットリスト

- **Row 1**: メインヘッダー（濃紺）
- **Block 1**: ヘッダーなしで直接チーム行が始まる
- **Block 2〜**: 先頭に中青のヘッダー行を挿入してブロックの区切りを示す
- warn（要対応の違反）があるチームは**黄色背景**、note（許容範囲の参考情報）のみのチームは**水色背景**で強調し、備考欄に理由を記載

列構成:
| 出演順 | ブロック内番号 | 出演開始時間 | チーム名 | 受付番号 | 曲名 | アーティスト名 | 出演時間 | 入りはけ時間 | 掛け持ちチーム... | 備考 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 1-1 | 13:00:00 | TEAM_A | 001 | ... | ... | 3:45 | 0:30 | TEAM_C | 掛け持ち間隔不足: TEAM_Cとの間隔が0:25:00（目安:1時間、最低:40分） |
| 2 | 1-2 | 13:04:15 | TEAM_B | 002 | ... | ... | 4:12 | 0:30 | | 掛け持ち間隔が目安未達: TEAM_Dとの間隔が0:50:00（最低40分は確保、目安1時間には未達） |
| 出演順 | ブロック内番号 | 出演開始時間 | チーム名 | 受付番号 | 曲名 | アーティスト名 | 出演時間 | 入りはけ時間 | 掛け持ちチーム... | 備考 |
| 3 | 2-1 | 13:30:00 | TEAM_C | 003 | ... | ... | 3:20 | 0:30 | TEAM_A | 掛け持ち間隔不足: TEAM_Aとの間隔が0:25:00（目安:1時間、最低:40分） |

- **受付番号**: 入力ファイルの受付番号列をそのまま転記する（列が無い場合は空欄）
- **備考**: 文句なしにクリアしていない項目がある場合、その理由を全て記載する（複数ある場合は`; `区切り）。全項目を完全に満たしている場合のみ空欄。希望時間帯に関する備考は、要約ではなく入力ファイルの原文をそのまま「（原文:「...」）」の形で引用する。

### Sheet2: 掛け持ちチェック表（掛け持ちペアがある場合のみ）

| チームA | チームB | 実際の間隔 | 目安/最低 | 判定 |
|---|---|---|---|---|
| TEAM_A | TEAM_C | 1:15:00 | 1時間 / 40分 | OK |

## エラー処理

| 状況 | 対応 |
|---|---|
| Spotify認証情報（`~/.claude/spotify_credentials.json`）がない | `references/spotify-setup.md` を案内 |
| Spotifyで曲が見つからない | スクリプトが列挙するので、ユーザーに再生時間（分:秒）を手動入力してもらい、`--duration-overrides '{"チーム名": 秒数}'` で再実行 |
| 掛け持ち制約を満たせない | 最善案を採用し ⚠ 警告をExcelに付記（黄色背景） |
| 入力ファイルの列名が違う | `--col-*` オプションで列名を指定する |
| ortoolsが未インストール | 自動的に貪欲法にフォールバックする（`pip install ortools`で厳密探索が有効になる旨を案内） |
| ハード制約込みで解なし | スクリプトが自動的に優先度の低い順に緩和して再探索する（Step 5-2参照）。全て緩和しても解なしの場合は貪欲法にフォールバックする |
| `--fixed-order-file`のチーム名が入力と一致しない | スクリプトがエラーで不足/余分なチーム名を表示するので、JSON配列を修正する |
| アーティスト名が`=`等で始まり値が消える | スクリプト側で自動的に文字列型として保存するため通常は発生しないが、手動でExcelを編集した場合は再度`=`等で始まっていないか確認する |
